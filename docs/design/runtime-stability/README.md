# Восстановление sport-brend.ru, 24 ноября 2026

Сервис оставался запущенным, но Nginx регистрировал тайм-ауты главной и конструктора. До восстановления потребление группы приложения достигало примерно 430–450 MiB при `MemoryHigh=384M`. Счётчик `memory.events high` превысил 138 тысяч, давление памяти доходило до 99% some / 94% full. OOM и автоматических перезапусков не было: процесс застревал в непрерывном reclaim. В access.log одновременно шло сканирование множества вариантов размеров изображений; часть внешних фотографий завершалась сетевыми тайм-аутами.

После принудительного завершения зависшего процесса и запуска главная вернулась к ответу примерно за 0,26 с. Оперативно снят порог `MemoryHigh`; общий жёсткий предел приложения остался 512 MiB. Другие сервисы не менялись.

Постоянное исправление:

- `next.config.ts`: один поток libvips на изображение, отключён кеш нативных операций Sharp. Дисковый кеш готовых изображений сохранён. Параметры проверены по установленному Next.js 16.4.6 (`image-optimizer/transform.js`).
- `deploy/multibook-preview-memory.conf`: heap Node.js 192 MiB, два потока libuv и две арены glibc; общий предел 512 MiB, без мягкого порога, вызывавшего reclaim. Остановка сервиса ограничена 15 секундами.
- Drop-in установлен только для `multibook-preview.service`; предыдущая конфигурация сохранена в каталоге резервных копий сервера. Изменение приложения оформлено отдельным PR поверх конструктора.

Дизайн, каталог, SQLite, server actions, вход, заказы и платежи не изменены. Проверки TypeScript и production build проходят. После публикации проверяются страницы, обработка серии изображений и состояние памяти. Скриншоты 1366 и 375 px находятся рядом.
