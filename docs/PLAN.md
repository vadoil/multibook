# Multibook — новый сайт: план

Решения пользователя (22.11.2026): свой сайт, сервер — VPS пользователя. **Уточнение 23.11: новый сайт работает параллельно с multi-book.ru на Tilda, а не заменяет его** — редиректов со старых адресов и переноса домена не будет; адрес нового сайта — `SITE_URL` в `.env`. Дизайн — по макетам Codex; до их появления делаем аккуратную базовую дизайн-систему на токенах, чтобы потом заменить оформление без переписывания логики.

## Стек

| Слой | Выбор | Почему |
|---|---|---|
| Фреймворк | Next.js (App Router) + TypeScript | Серверный рендер для SEO, API-роуты для корзины, оплаты, админки — в одном приложении |
| Стили и анимация | Tailwind CSS + Motion | Быстрая вёрстка по макетам, выразительные анимации и карусели |
| База данных | SQLite + Drizzle ORM | Для одного магазина на одном VPS хватает с запасом; резервная копия — копия файла. При росте переезд на PostgreSQL без смены ORM |
| Авторизация | Better Auth (email + пароль, роли customer / admin) | Работает с Drizzle, есть роли и сессии |
| Оплата | ЮKassa API (платёж → редирект → вебхук) | Уже используется в Tilda |
| Доставка | СДЭК API (курьер, ПВЗ) + самовывоз | Как сейчас |
| ИИ для контент-завода | OpenAI-совместимый роутер (ключ пользователь даст позже), только на сервере | Ключ никогда не попадает в браузер |
| Деплой | Docker Compose на VPS: приложение + Caddy (HTTPS) | Один `docker compose up`, автоматические сертификаты |

## Данные

- **Каталог** импортируется скриптом из публичного API Tilda Store (`store.tildaapi.com`) — без доступа к редактору Tilda. Импорт можно повторять: обновляет цены и наличие по `uid`.
- **Товар**: uid Tilda, название, slug, цена, старая цена, артикул, остаток, тип (Обложки, Блоки, Диски, Тетради, Блокноты, Аксессуары, Фотокниги), характеристики (формат, разметка, материал, диаметр), галерея, описание.
- **Нормализация при импорте**: «A4»/«А4» → один формат; число листов, бумага и линовка блоков; диаметр, цвет и фасовка дисков (8 / 100 / 1000 шт); комплект или одна обложка.
- **Заказ**: позиции с ценой на момент заказа, покупатель, доставка, оплата, статус (новый → оплачен → собран → отправлен → получен / отменён), сборка конструктора как отдельная группа позиций.
- **Сборка**: сохранённые конфигурации конструктора (обложки, блоки, диски, дополнения) — в кабинете покупателя.
- **Контент**: идеи, посты, карусели, сценарии рилсов, статусы (идея → черновик → на проверке → готово → опубликовано), план публикаций, привязка к товарам.

## Разделы сайта

**Витрина**: главная, каталог с фильтрами, карточка товара, живой конструктор, корзина и оформление, «Как работает переплёт», корпоративные заказы (форма заявки), оплата и доставка, контакты, политика.

**Кабинет покупателя**: заказы и их статусы, сохранённые сборки («собрать снова»), адреса и данные для счёта юрлица.

**Админка**: заказы (смена статуса, комментарии), товары (импорт из Tilda, правка, наличие), заявки корпоративных клиентов, контент-завод, пользователи.

**Контент-завод** (в админке):
1. Бриф: товар или тема, сценарий, площадка, формат (пост, карусель, рилс, баннер).
2. Генерация вариантов текста и раскадровки через ИИ-роутер с правилами бренда (крупный товар, конкретный сценарий, без обещаний без доказательств).
3. Редактор, проверка «привязки к реальному SKU», статусы, план публикаций.
4. Экспорт: тексты, раскадровки, HTML-баннеры карусели (картинки рендерятся на сервере).

## Этапы

| # | Этап | Результат |
|---|---|---|
| 0 ✓ | Каркас, база, импорт каталога, каталог и карточка | Сайт открывается локально с реальными товарами |
| 1 ✓ | Конструктор, корзина, оформление заказа (без онлайн-оплаты) | Заказ попадает в базу |
| 2 ✓ | Кабинет покупателя, админка заказов и товаров | Магазином можно управлять |
| 3 ✓ (демо) | ЮKassa и СДЭК | Реальная оплата и расчёт доставки |
| 4 ✓ (первая версия) | Контент-завод, связь с Ozon и Wildberries | Пост, карусель и рилс из карточки товара; остатки площадок в админке |
| 5 | Дизайн по макетам Codex, «вау»-анимации, мобильная версия | Финальный вид |
| 6 | Деплой на VPS на свой адрес (параллельно с Tilda) | Запуск |

Этап 1 сделан так:
- Конструктор `/constructor`: обложка → один блок листов (+ запасные) → диски 8 шт. Ёмкость: 18 мм до 64 листов, 24 мм до 86; при 65+ листах диаметр 24 ставится сам. Блоки по 104 листа больше ёмкости — показываем предупреждение, но не запрещаем (уточнить у владельца, на каких дисках они собираются).
- Свой конструктор на каждый формат (`src/lib/formats.ts`): А5 — из частей; мини евро 85×160 и мини куб 85×95 — готовый мини-блокнот (в нём блок, диски 19 мм, ручка) + запасные блоки + по желанию цветные диски 18 мм. Узкие блоки 9,5×21 пока не в конструкторе — неясно, к какому блокноту они.
- Сборка кодируется в адресе `?f=<a5|euro|cube>&c=<id обложки/блокнота>&b=<id>[.<кол-во>],…&d=<id дисков>`; с карточки товара — `?with=<slug>` (формат определяется сам).
- Корзина хранится в браузере, цены и наличие всегда берутся с сервера; заказ пересчитывается по базе.
- Заказ: `orders` + `order_items`, номер = 1000 + id, страница `/order/<token>` без входа.

Этап 2 сделан так:
- Вход — свой, без Better Auth: почта + пароль (scrypt), сессия в httpOnly-cookie, в базе только SHA-256 токена (`src/lib/auth.ts`). Ограничение попыток входа — в памяти процесса (на одном сервере достаточно). Подтверждения почты нет: нет почтового сервиса; добавим вместе с письмами о заказе.
- Кабинет `/account`: вход/регистрация, мои заказы, данные доставки (подставляются в корзину). Заказы без входа к кабинету не привязываются — почта не подтверждена.
- Админка `/admin` (роль admin): сводка, заказы (статусы, стоимость доставки → пересчёт итога, заметка, история `order_events`), товары (правка, скрыть/показать), кнопка импорта из Tilda. Правленый товар помечается `lockedAt` — импорт не трогает его цену, название, наличие, описание и видимость.
- Права админа: человек регистрируется на сайте, затем `npm run admin:grant -- почта`. Для разработки — `npm run dev:admin` (пароль в `.env.local`).
- Уведомления о новом заказе — Telegram (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`); без них только лог сервера.

Этап 3 сделан так (код настоящий, без ключей — заглушки):
- Оплата `src/lib/payments.ts`: ЮKassa API v3 (платёж с редиректом, ключ идемпотентности, чек 54-ФЗ по `YOOKASSA_RECEIPTS=1`), вебхук `/api/payments/yookassa` перезапрашивает платёж по API и сверяет сумму. Без ключей — демо-страница `/pay/demo/<id>`; в продакшене демо только при `DEMO_PAYMENTS=1`.
- Платить можно, когда доставка посчитана и заказ «новый» или «подтверждён». Оплата переводит заказ в «Оплачен», пишет историю и уведомляет менеджера.
- Доставка `src/lib/delivery.ts`: СДЭК API v2 (OAuth, поиск города, `tarifflist`, режимы 4 «до ПВЗ» и 3 «до двери»); без ключей — демо-формула. В корзине расчёт виден сразу, при заказе сервер считает заново.
- Вес посылки — оценка по типу товара (`WEIGHT` в delivery.ts). Нужны реальные веса и габариты от владельца.
- Выбор ПВЗ на карте (виджет СДЭК) и создание накладной в СДЭК из админки — ещё не сделаны.
- Схема: `drizzle-kit push` на SQLite при изменении связей пересоздаёт таблицу и однажды упал на середине. Перед запуском на сервере перейти на миграции (`drizzle-kit generate` + `migrate`).

## Правовое

Сайт хранит персональные данные покупателей (имя, телефон, адрес) — по 152-ФЗ сервер с базой должен быть в России, нужна политика обработки данных и согласие в формах. Проверить, где расположен VPS, до запуска.
